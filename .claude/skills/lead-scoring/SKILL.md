# Lead Scoring — приоритизация входящих лидов

Скилл ранжирует лиды 0–100 по вероятности конверсии в покупку за 14 дней и выдаёт две вещи на руки: красивый HTML-отчёт (TOP-10 + сегменты A/B/C + инсайт) и CSV со скорами по каждому лиду.

## Когда использовать

- Пользователь выгрузил лиды из CRM и не знает, кому звонить первым.
- РОП хочет посмотреть, как методология скоринга отработает на его воронке.
- Участник AI Camp Almaty 2026 проходит воркшоп «Скоринг лидов».

## Поток работы

1. **Спроси про CSV.** Сначала уточни одной строкой: «Прикрепи свой CSV с лидами или скажи `используй тестовый` — пройдём на демо-наборе из 50 строк».
2. **Если пользователь сказал «тестовый» / не прикрепил файл** → возьми `sample-leads.csv` из директории скилла. В отчёте пометь источник `(demo run · sample-leads.csv)`.
3. **Если приложили CSV** → прочитай первые 5–10 строк, опознай колонки (см. «Адаптивный mapping»). Покажи пользователю короткий confirm: «Я опознал: ID = `Сделка_ID`, name = `Имя клиента`, crm_notes = `Комментарии`, behavior-данных не вижу → переключаюсь на minimal-режим. Поехали?». Жди подтверждения максимум одной строкой («да» / «ок» / «поехали»). Если очевидно — не спрашивай, просто скажи что опознал и продолжай.
4. **Скоринг.** Применяй методологию (см. «Методология»). Для каждого лида: tier (rich / minimal), score 0–100, категория A/B/C, top-3 причины, первое действие.
5. **Для TOP-10** дополнительно сгенерируй `opening_line` — что сказать в первые 30 секунд звонка, опираясь на `crm_notes`.
6. **Сегментная аналитика.** Посчитай раскладку A/B/C × rich/minimal, % воронки, рекомендации.
7. **Инсайт.** Один абзац (3–5 предложений): какой канал даёт A, есть ли разрыв rich/minimal, что подкрутить в tracking или crm_notes.
8. **Вывод** — см. «Формат вывода». HTML-отчёт + scored CSV.
9. **После доставки** — короткое follow-up меню (см. «После доставки»).

## Адаптивный mapping

В CRM разные команды называют колонки по-разному. Скилл должен опознавать **логические поля** независимо от имён.

### Логические поля и как их искать

| Логическое поле | Что ищем в имени колонки | Что ищем в значениях |
|---|---|---|
| `lead_id` | id, ID, Сделка_ID, Lead Id, Deal ID, № | уникальный integer/uuid |
| `created_at` | created, дата создания, date, добавлен | дата формата YYYY-MM-DD или DD.MM.YYYY |
| `source` | source, источник, канал, utm_source, откуда | instagram_ads, google_ads, organic, referral, webinar, форма с сайта, входящий звонок |
| `name` | name, имя, ФИО, fullname, контакт | имена людей |
| `position` | position, должность, role, job_title | должность |
| `company_size` | company_size, размер компании, employees | solo, small, medium, large, число |
| `phone_provided` | phone, телефон, есть телефон | bool / непустое поле |
| `email_opened_count` | email_opens, opened, открытий | integer |
| `link_clicked` | clicked, click, переход | bool |
| `material_downloaded` | downloaded, скачал, download | bool |
| `webinar_attended_min` | webinar, вебинар, attended_min | integer (минуты) |
| `last_contact_days_ago` | last_contact, последний контакт, дней назад | integer |
| `touches_count` | touches, касания, contacts_count | integer |
| `crm_notes` | notes, заметки, комментарий, comments, описание | свободный текст |

### Что делать, если поля не нашёл

- **`crm_notes` отсутствует** → предупреди пользователя: «Главный сигнал для minimal-лидов — комментарий менеджера в CRM. У тебя такой колонки нет, скоринг будет менее точным. Продолжаем?». Если согласен — иди по тому, что есть.
- **`created_at` отсутствует** → попроси указать или работай без recency-сигнала (вес перераспредели на остальные).
- **`lead_id` отсутствует** → сгенерируй порядковый.
- **Behavior-колонки (email/click/download/webinar) отсутствуют целиком** → переключи весь датасет в minimal-режим, без вопросов.

### Confirmation message — формат

Когда колонок много и mapping очевидный, отправь одну строку без вопросов:
> «Опознал колонки. Behavior-данных нет → minimal-режим для всех. Скорю…»

Когда mapping неоднозначный (например, две колонки похожи на `crm_notes`):
> «Подтверди: `Описание сделки` или `Заметки менеджера` использовать как crm_notes? (короткое слово — название колонки)»

## Методология скоринга

### Базовые веса (когда behavior-колонки заполнены)

| Группа | Вес |
|---|---|
| 1. Behavior signals | 40% |
| 2. Fit signals | 30% |
| 3. Recency | 20% |
| 4. Touch quality (crm_notes + phone + touches) | 10% |

### Адаптивные веса (когда behavior-колонки пустые)

Если у лида все четыре `email_opened_count` / `link_clicked` / `material_downloaded` / `webinar_attended_min` пустые → перераспределяй:

| Группа | Вес |
|---|---|
| 1. ~~Behavior signals~~ | 0% |
| 2. Fit signals | 25% |
| 3. Recency | 25% |
| 4. **Touch quality** | **50%** ← главный сигнал |

Когда tracking не подключён, **главный носитель сигнала — `crm_notes`**.

### 1. Behavior signals

- `material_downloaded = true` → **+25**
- `webinar_attended_min ≥ 30` → **+30**; 10–29 → **+15**
- `link_clicked = true` → **+10**
- `email_opened_count` ≥ 5 → **+15**, 3–4 → **+10**, 1–2 → **+5**, 0 → **0**

### 2. Fit signals

- `position` релевантна `course_interest` (например, `маркетолог` для digital-маркетинга) → **+20**
- `position` указана и осмысленная (не `студент`, не `школьник`, не пусто) → **+10**
- `company_size` small (5–30) → **+10**, medium+ → **+15**, пусто → **+5**
- `course_interest` совпадает с типичной траекторией роста для этой position → **+15**

### 3. Recency

- `created_at` ≤ 3 дней → **+20**
- 4–7 дней → **+10**
- 8–14 дней → **+5**
- 15–30 дней → **−10**

### 4. Touch quality

Читаем `crm_notes` внимательно. **Это самая важная группа, когда behavior-данных нет.**

**Strong buying signals (+30 каждый, можно набрать несколько):**
- «оплата», «оплатить», «счёт», «ОФД», «1С», «карта компании», «корпоративный», «ТОО»
- «срочно», «сегодня», «понедельник», «эта неделя», «ближайший поток»
- «когда старт», «ближайшие даты», «расписание»
- «бюджет одобрен», «деньги есть»
- «КП», «коммерческое предложение»
- «входящий звонок» (сам позвонил)
- «корпоративно на N человек»

**Moderate signals (+15 каждый):**
- «рассрочка»
- «программа», «материалы»
- «сравниваю с другими», «выбираю»
- «попросил перезвонить»
- «коллега учился у нас» (warm referral)

**Weak / negative signals (+0 или −):**
- «просто посмотреть», «интересно для саморазвития» → **+0**
- «не подходит уровень», «уже знаю» → **−15**
- «после декрета через год», «потом», «через месяц» → **−10**
- crm_notes пустое → **+0** (нейтрально)

**Прочее:**
- `phone_provided = true` → **+5**
- `touches_count` 1–3 → **+5**, 0 или >5 → **0**

### Категории (итоговый score 0–100)

- **A** (приоритет звонка сегодня): score ≥ 65
- **B** (звонок 48ч / nurture): 40 ≤ score < 65
- **C** (email / disqualify): score < 40

### Edge cases

- Пустые behavior-колонки → не штрафуй, переключайся на адаптивные веса.
- `phone_provided = false` → в `первое действие` ставь **email** или **disqualify**, не «звонок».
- Одинаковый score → сортируй по `created_at` (свежий выше).
- `position` пустое или вида `user_12345`, `test_user`, технический email → мусор, автоматом C-категория.

## Формат вывода

### HTML-отчёт

Используй шаблон `assets/report-template.html` из директории скилла как основу. Шаблон содержит inline CSS (no external deps), self-contained, открывается в любом браузере офлайн.

Заполни эти секции (плейсхолдеры в шаблоне):
- **Заголовок:** «Lead Scoring · {company_or_demo} · {date}»
- **Summary badges:** total leads, A count, B count, C count, % воронки в A
- **TOP-10 cards:** имя, score, категория, источник + `opening_line` для каждого
- **Ранжированная таблица:** все 50/100/500 лидов с цветовой пометкой строки по категории (A — teal, B — yellow, C — gray)
- **Сегменты:** таблица «Категория | Кол-во | rich | minimal | % воронки | Рекомендация»
- **Инсайт:** один абзац 3–5 предложений

### CSV (scored)

Колонки = все оригинальные + добавь в конец:
- `tier` (rich / minimal)
- `score` (0–100)
- `category` (A / B / C)
- `top_reasons` (3 фактора через `; `)
- `first_action` (звонок / email / nurture / disqualify)
- `opening_line` (только для TOP-10, иначе пусто)

### Куда писать файлы

**В Claude Code:**
- Если есть директория `active/` в CWD — пиши в `active/lead-scoring/`
- Иначе — пиши в `./lead-scoring-output/` в CWD
- Имена: `report-{YYYY-MM-DD-HHMM}.html` и `scored-leads-{YYYY-MM-DD-HHMM}.csv`
- После записи покажи пользователю абсолютные пути обоих файлов и предложи открыть HTML (`open report-*.html` на macOS)

**В Claude app / web (claude.ai):**
- HTML-отчёт → создай как artifact (тип `text/html`), пользователь сразу видит в превью
- CSV → создай через инструмент code execution и предложи download
- Если code execution недоступен — отдай CSV-данные блоком кода в чате, скажи: «Скопируй блок в файл `.csv` или сохрани этот ответ»

### Не делай

- Не вставляй полную ранжированную таблицу в чат — она в HTML. В чат — короткое summary (3 строки: total / A·B·C / путь к HTML).
- Не используй emoji.
- Не выдумывай данные. Если поле пустое — пиши «—» или оставляй пустым.

## После доставки

Когда отчёт готов, спроси одной строкой:
> «Готово. Хочешь: (а) поставить на cron — пройдёмся по [monday-action](references/monday-action.md); (б) у тебя B2B и нужны другие веса — [adapt-to-b2b](references/adapt-to-b2b.md); (в) посмотреть, как выглядит эталонный прогон — [example-output](references/example-output.md)?»

Не предлагай все три варианта раскрытыми — пользователь выберет.

## Когда НЕ использовать этот скилл

- Реактивация старых лидов (>30 дней) — это другая задача.
- B2B-сделки с длинным циклом и несколькими ЛПР — методология сильно отличается, читай `references/adapt-to-b2b.md` и предложи пользователю адаптированный промпт.
- Outbound-разведка холодных контактов — это `ai-camp-enrich-and-pitch`, не этот скилл.
